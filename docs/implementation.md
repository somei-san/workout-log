# 実装方針

[ux-design.md](ux-design.md) の仕様を、iOS アプリとして作るための方針。用語は ux-design.md に合わせる。

## 技術スタック

- 画面: SwiftUI
- データの保存: [GRDB.swift](https://github.com/groue/GRDB.swift)(SQLite を Swift から扱うライブラリ)
  - 経過日数・頻度での並べ替えと、分析の集計を SQL でデータベースの中で済ませる。記録が増えても、必要な結果だけを読み出せる。
  - `DatabaseMigrator` に変更を順番に登録して、テーブルを変える。テーブルを変えるときに記録を移し替える処理も、SQL で書ける。
  - SwiftData は、記録をオブジェクトとして読み込んでから Swift で集計する書き方になりやすく、変換を伴うテーブルの変更で細かく制御できる範囲も狭いので使わない。
- 画面の更新: GRDB の `ValueObservation` で、データの変更を画面に伝える。

## テーブル

| テーブル | 列 | 備考 |
|---|---|---|
| `exercise`(種目) | `id`, `name`, `part`, `isHidden`, `initialRowCount` | `initialRowCount` は最初に並べるセット数(0〜10) |
| `record`(1 回の記録) | `id`, `exerciseId`, `performedAt`, `utcOffset`, `memo` | `performedAt` は UTC の日付と時刻、`utcOffset` は記録した場所の UTC との時差(分) |
| `workoutSet`(セット) | `id`, `recordId`, `position`, `weight`, `reps`, `rpe`, `rir` | `position` は記録の中の順番 |

### 部位

`part` には `chest` のような英語のコードを保存する。表示名と、部位の見方で区切る順番(胸、肩、背中、腕、腹、足、その他)は、Swift の enum 1 か所で持つ。表示名を変えても、テーブルを変えずに済むようにするため。

### 日付と時刻

- 日付は、`performedAt` に `utcOffset` を足した、記録した場所の時刻から切り出す。日本で付けた記録なら、SQL では `date(performedAt, '+540 minutes')` の形になる。GRDB は `Date` を UTC の文字列で保存するので、そのまま `date()` で日付を切り出すと、日本の朝 9 時より前の記録が前日になる。
- 記録した場所の時刻から日付を切り出すので、別のタイムゾーンで開いても、過去の記録の日付は変わらない。
- 経過日数、同じ日の判定(種目の履歴で時刻を出すか)、今日か前日以前か(編集モードか閲覧モードか)は、どれもこの日付で決める。
- 1 回の記録の並び順は (`performedAt`, `id`) とする。日付と時刻を変えて同じ時刻の記録ができても、前回が一つに決まるようにするため。

### 作る・消す

- 1 回の記録は、重さと回数の入った最初のセットができた時点で `record` に行を作る。空の行は画面の中だけで持ち、保存しない。
- 最初のセットの前に日付と時刻を変えたときは、画面の中で持っておき、最初のセットを保存するときにその日付と時刻で `record` の行を作る。
- `record` から `exercise` へ、`workoutSet` から `record` へ外部キーを張り、`ON DELETE CASCADE` を付ける。種目を消すとその記録とセットが、記録を消すとそのセットが、データベースの中で消える。
- 最後のセットを消すときは、同じトランザクションで `record` の行も消す。

### 保存しない値

次の値は保存せず、表示するときに計算する。経過日数と頻度の計算のため、`record` に (`exerciseId`, `performedAt`) の index を張る。

- `record` から: 経過日数、頻度
- `workoutSet` から: ボリューム、推定 1RM、最大重量、トップセット、セット数

強度は `rpe` と `rir` を別の列で持つ。設定で強度の種類を切り替えても、過去の値の意味が混ざらないようにするため。

## マイグレーション

Xcode から実機に入れるアプリはいつも DEBUG ビルドで、実機のデータベースには実際の記録が入る。そのため、次の 2 つを守る。

- `eraseDatabaseOnSchemaChange`(テーブルの定義が変わったらデータベースを消す設定)は、DEBUG でも有効にしない。
- 実機で一度動かしたマイグレーションは書き換えない。テーブルの変更は、新しいマイグレーションとして足す。

## 端末の設定に持つ値

`UserDefaults`(アプリの設定を保存する iOS 標準の仕組み)に持つ。どれもデータベースの記録とは独立していて、消えても初期値に戻るだけで済むため。

- 強度の欄: 非表示、RPE、RIR
- 種目の履歴の表示項目: ボリューム、推定 1RM、最大重量、トップセット、セット数のそれぞれの表示と非表示
- ホームの並べ方: 「すべて」と「部位」の見方ごとに 1 つ

## アイコンと色

App アイコンと部位の形は、`scripts/make-icons.swift` が CoreGraphics で描き、`WorkoutLog/Assets.xcassets` に書き出す。部位の色とアクセントカラーも、このスクリプトが値を持ち、アセットカタログの色として書き出す。形や色を変えるときは、このスクリプトを直して `swift scripts/make-icons.swift` で書き出し直す。書き出した画像と色は手で編集しない。

- App アイコン: 1024×1024 の不透明な PNG を 1 枚。黒のグラデーションにライムのダンベル
- 部位の形: 部位ごとに、体の残り(`<部位>-base`)と鍛える部位(`<部位>-target`)の 2 枚のテンプレート画像。どちらもベクターの PDF。1 枚の画像には 1 色しか付けられないので 2 枚に分け、画面の側で部位の色の濃さを変えて重ねる。その他は鍛える部位の画像をダンベルにし、体の残りの画像は空にする
- アクセントカラー: App アイコンのライム。ライトでは、白の背景で文字が読めるよう暗いライムにする

## 動かす環境

- 対応する iOS: 18 以上。利用者が作者本人だけで、古い iOS に合わせる理由が無いため。
- 端末への入れ方: Xcode から自分の iPhone に直接入れる。
  - 署名のチームの ID は、リポジトリの直下に `Local.xcconfig` を作って `DEVELOPMENT_TEAM = <チームの ID>` と書く。git では追跡せず、`Signing.xcconfig` から読む。
  - 無料のアカウントでは、入れたアプリが 7 日で起動できなくなり、Xcode から入れ直す([Apple Developer Forums](https://developer.apple.com/forums/thread/71283) の回答による。Apple の公式ドキュメントでは確かめていない)。

## 見た目の回帰テスト

各画面を UI テスト（`WorkoutLogUITests/SnapshotTests.swift`）で撮り、[swift-snapshot-testing](https://github.com/pointfreeco/swift-snapshot-testing) で基準の画像（`WorkoutLogUITests/__Snapshots__/`）と比べる。キーボードとシートも写すため、ビューを直接描かずに、シミュレーターの画面を撮る。

- 撮る条件: ライトとダーク × 標準と XXXL の文字サイズの 4 通り。XXXL は、アクセシビリティの設定を使わずに選べる中で一番大きい文字サイズ。
  - ダークは、起動引数 `-uiTestingDark YES` でアプリの画面をダークにする。iOS 27.0 のシミュレーターでは、外観の設定をダークにしてもアプリに届かないことがあるため。
- ホームの並べ替えのメニューと長押しのメニューは撮らない。開くたびにメニューの位置が数ピクセルずれることと、外を押しても閉じないことがあるため。
- ホームの部位の見方は、「部位」を押さずに、起動引数 `-home.mode part` で開いて撮る。押して切り替えると、切り替えの文字と枠の描き方が起動のたびに少し変わるため。
- 撮るたびに見た目が変わらないよう、次のものを固定する。
  - 今の時刻。起動引数 `-uiTestingNow` で渡す。
  - タイムゾーン: 日本時間。
  - 言語: 日本語。
  - ステータスバーの表示。
  - 入力欄のカーソル。UI テストでは透明にする。点滅して、撮るたびに写り方が変わるため。
- 撮る端末: `scripts/vrt-simulator.sh` が作る、iOS 27.0 の iPhone 17 の専用のシミュレーター。手元と CI のどちらもこのスクリプトで用意する。別のシミュレーターでは画像が一致せず、落ちることがある。
- 比べ方: 違う画素が 0.01% 未満で、どの画素も見た目でほぼ同じ色なら一致とする。キーパッドのガラス越しにぼかして見える部分の色が、起動によってわずかに変わるため。一致しなければ 10 回まで撮り直し、どれも一致しないときだけ落とす。キーパッドの部分が一時的に違って写ることがあるため。
  - ステータスバーの部分は、比べる前に塗りつぶす。時刻の表示を固定しても、手元と CI で時刻の部分の画素が違うため。
- CI: 基準の画像と一致しない画面があると落ちる。基準の画像との差分の画像は、CI の成果物の xcresult に入る。CI はテストを 5 つのジョブに分け、別々の runner で同時に回す。分け方は `.github/workflows/test.yml` の `matrix` にある。
- 手元で回すとき: `scripts/test.sh` で回す。専用のシミュレーターを用意し、引数で選んだ UI テストだけを回す（引数が無ければ単体テストだけ）。全部を回すと 30 分ほど Mac とシミュレーターがふさがるので、直した画面のテストだけを選ぶ。撮る条件はクラスで分かれていて、ライト・標準は `SnapshotTests`、ダークは `DarkSnapshotTests`、XXXL は `LargeTextSnapshotTests`、ダーク・XXXL は `DarkLargeTextSnapshotTests`。

  ```sh
  # 記録の画面を、ライト・標準とダーク・XXXL で撮る
  scripts/test.sh SnapshotTests/testRecord DarkLargeTextSnapshotTests/testRecord
  ```

- 意図して見た目を変えたときは、手元で違いの出た画像を撮り直してコミットする。

  ```sh
  TEST_RUNNER_SNAPSHOT_TESTING_RECORD=failed scripts/test.sh SnapshotTests/testRecord DarkLargeTextSnapshotTests/testRecord
  ```

  画面を足したときは、環境変数を付けずに回しても、基準の画像が無い画面だけが記録される（記録した回のテストは落ちる）。

## 実装の順番

1. Xcode のプロジェクトを作り、GRDB を Swift Package Manager で入れる
2. テーブルと `DatabaseMigrator` の最初のマイグレーションを作る
3. ホーム → 種目の追加 → 種目の履歴 → 種目の記録。ホームは初期値の並べ方(経過日数：降順)で並べ、並べ替えのメニューは実装の順番の 5 で作る
4. 種目の非表示と削除、種目の設定、1 回の記録とセットの削除、日付と時刻の変更、閲覧モード
5. 並べ替え、設定、分析、CSV の書き出し
